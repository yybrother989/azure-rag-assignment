## Design Context

### Users
Two co-equal audiences for the Chainlit frontend at `src/app.py`:
1. **Reviewer / grader** of this take-home assignment — wants to audit the LangGraph trace, see that intent → plan → retrieve → select → generate → cite is *actually* happening, judge engineering rigor.
2. **End-user employee** searching the knowledge base — wants the answer with sources, doesn't care about the agent loop.

The interface must serve both: clean answer-first surface by default, with the full agentic trace one keystroke / hover / toggle away. The trace is the differentiator — it should never be hidden, but it shouldn't be the first thing a casual user sees either.

### Brand Personality
Three words: **observable, technical, unflinching.**

Voice: terse, factual, log-line cadence. No marketing copy, no emojis (the codebase already uses ①②③ Unicode markers — keep that level, no further). Numbers and IDs are first-class citizens, not hidden behind tooltips. The pipeline does not apologize for being a pipeline.

Emotional goal: the reviewer should think "this person has built a real system" within three seconds of opening the page. The employee should think "I trust this answer because I can see where it came from."

### Aesthetic Direction
**Bold technical / brutalist log-stream.**

- **Type**: monospaced display (e.g. JetBrains Mono, Berkeley Mono, IBM Plex Mono) for headings, step labels, IDs, latencies, token counts. Clean grotesk (e.g. Inter Tight, Söhne, Geist) for the answer body — readable prose, not a wall of mono.
- **Color**: tinted near-black + tinted near-white, one signal accent (lean amber/sodium-yellow or signal-orange — *not* the AI cyan/violet/neon-green palette). Status semantics: muted green for ✓, muted amber for in-flight, muted red for error. No gradients. Hairline rules (`1px` tinted-neutral) instead of cards.
- **Layout**: hard left alignment, generous vertical rhythm between sections, **tight** rhythm within a step. Big numbers (latency, token count, cost) get visual weight. Step blocks are stacked log entries, not nested card components.
- **Theme**: light + dark, system-aware. Light = paper-white tinted warm, ink near-black tinted warm. Dark = soot near-black tinted warm, paper near-white tinted warm. Both must look intentional — not "the same design with colors flipped."

**Anti-references** (do NOT look like): generic ChatGPT clones, glassmorphic AI dashboards, cyan-on-black "agent" UIs, rounded-card-with-icon Bento grids, gradient buttons.

**References** (the *vibe* to aim for): Linear's command palette, the Vercel deploy log, htop / btop, a research preprint, observability tools (Honeycomb, Axiom).

### Design Principles
1. **The trace is the product.** Default to *showing* the steps, not summarizing them. Information density beats whitespace decoration.
2. **Two layers, one surface.** Answer + sources are the primary read. The full trace is the secondary read on the same page — a toggle, a sidebar, a collapsed drawer. Never a different route.
3. **Numbers over adjectives.** "412ms · 6 chunks · 3 kept · $0.007" beats "fast and accurate." Every step earns at least one quantitative readout.
4. **One accent, used rarely.** The signal color marks state changes (in-flight → done, current step) and citations. If it's everywhere, it's nowhere.
5. **Mono for structure, sans for prose.** Mono signals "this is data the system produced." Sans signals "this is meant to be read." Don't blur the line.
